# nhop-bench

**有向グラフを何ホップ辿れるかを LLM で測る。正解はデータ側から機械生成する。**

「ナレッジグラフが要るのは LLM が関係を辿れないから」とよく言われます。では**何ホップから辿れなくなるのか**。
モデルを大きくすれば越えられるのか。グラフを1歩渡すと何が変わるのか。

このリポジトリは、その3つを測るための最小の道具です。

## なぜ Minecraft のクラフトツリーか

**正解が公開されていて機械可読だから**の1点です。

このジャンルの評価は「公開された正解データが無いので人手でアノテーションする」のが通例で、
そこが弱点になっています。ゲームのクラフトレシピは、ゲーム自身が正解を配っています。

クラフトは有向グラフです。`Polished Andesite Stairs` の材料を最後まで展開するには4段辿ります。

```
polished_andesite_stairs → polished_andesite → andesite → diorite → cobblestone, quartz
```

答えは2語ですが、4段の知識が要ります。**採点は簡単なのに、深さで難しくなる。**

## 測ってわかったこと (2026-09-05)

qwen3.5 の5サイズ × 2条件 × 101問 = 1,010回。温度0、パース失敗0件。

条件は2つです。`bare` は何も渡さない。`graph` は**直下の材料だけ**を渡す (葉までの答えは渡さない)。

**level 1 は集計から外しています。** 段数1では直下の材料＝葉なので、`graph` 条件が
答えそのものを渡すことになり、測れるのは知識ではなく指示追従だからです。

### グラフは recall を上げる。precision を保てるのは 9B 以上だけ

L2以上、n=71。

```
              bare rec/prec     graph rec/prec    完全一致 bare→graph
0.8b            0.11 / 0.02        0.05 / 0.04       0.0% →  0.0%
2b              0.10 / 0.04        0.09 / 0.05       0.0% →  0.0%
4b              0.26 / 0.19        0.33 / 0.16      12.7% →  1.4%   ← 悪化
9b              0.41 / 0.39        0.56 / 0.53      35.2% → 49.3%
35b-a3b         0.24 / 0.23        0.36 / 0.35      18.3% → 31.0%
```

**4b はグラフを渡すと完全一致が 12.7% → 1.4% に落ちます。** recall は 0.26 → 0.33 と
上がっているので、正しい材料は受け取れています。落ちているのは precision です。

理由は応答を見れば分かります。**渡した中間物をそのまま答えに混ぜています。**

```
Spruce Stairs   正解 [spruce_log]   渡した直下 [spruce_planks]

  bare  → ["spruce_wood"]                     誤り
  graph → ["spruce_log", "spruce_planks"]     正しい材料 + 渡された中間物
```

課題文には「中間物は挙げるな」と書いてあります。4b は直前に見せられた語を落とせません。
**グラフを足せば精度が上がるとは限りません。使えるだけの容量が要ります。**

### 大きいほうが強いとは限らない、ただし条件付き

`qwen3.5:35b-a3b` は `qwen3.5:9b` に負けています (L2以上、`bare` 18.3% 対 35.2%)。
このモデルの 35b は総パラメータで、**a3b は MoE のため1回の推論で動くのは約3B ぶん**です。

**ただし、この負けを「MoE だから」で説明するのは誤りでした。** 上の測定はすべて
**推論 (thinking) を切った状態**です。この系列は思考前提の設計なので、切ったこと自体が交絡します。

35b だけ思考を有効にして測り直すと、**符号が反転します**。

```
35b-a3b (L2以上 n=71)   bare      graph      差
思考なし                18.3%     31.0%    +12.7
思考あり                28.2%     19.7%     -8.5
```

思考は記憶からの想起には効き (18.3 → 28.2)、**渡された文脈への引きずられを強めます**
(31.0 → 19.7)。落ちた問題は 4b と同じ形でした。

```
Birch Boat    正解 [birch_log]    渡した直下 [birch_planks]
  思考あり → ["birch_log", "birch_planks"]    正解 + 渡されたものを混ぜる
Spruce Door   正解 [spruce_log]   渡した直下 [spruce_planks]
  思考あり → ["spruce_planks"]                渡されたもので止まる
```

この現象は文献で **contextual entrainment** と呼ばれ、モデルの大きさで現れ方が変わることが
報告されています。7B 未満では正しい文脈でも成績を落とすという報告
([arXiv:2603.11513](https://arxiv.org/html/2603.11513)) は、このベンチの 4b 悪化 / 9b 改善と
境界が一致します。

**9b の思考ありは測れていません。** 構造化出力を指定すると空配列を返し、外すと出力上限を
思考に使い切って答えに到達しません (RTX 4070 では時間に収まらず断念)。
したがって **「35b は 9b より弱い」と言えるのは思考を切った条件に限ります。**

失敗の型が違うことは、思考を切った条件では観察できました。L2以上の `bare` で
「途中で止まった」(直下の材料をそのまま答えた) が **35b は52%、9b は17%**。
**35b は展開せずに止まり、9b は展開して間違えます。**

### 段数で崩れるのは L3 から

9b の `graph` 条件が最も明瞭です。

```
L2 70%  →  L3 37%  →  L4 22%
```

L1 と L2 は問題の難易度が揃っていないので比較していません
(L1 には `Mace ← breeze_rod + heavy_core` のような難問が混ざります)。

## 使う

```bash
python3 scripts/build_dataset.py --version 26.1          # 正解データを作る
OLLAMA_HOST=http://your-gpu:11434 \
  python3 scripts/run_bench.py --models qwen3.5:9b       # 回す
python3 scripts/run_bench.py --models X --think          # 推論を有効にする
python3 scripts/analyze.py results/2026-09-05-run.json   # 集計
```

Anthropic のモデルは `--models claude-sonnet-5` と `ANTHROPIC_API_KEY` で回ります。
依存パッケージはありません (標準ライブラリのみ)。

## 正解データの作り方

`datasets/minecraft-pc-26.1.json` はスクリプトが機械生成したものです。**人手のアノテーションはありません。**

```
アイテム              1,506
クラフト可能            887
エッジ                2,261
分岐ありで除外           439
葉が実は可craftで除外     57
正解データ              372   段数分布 {1:161, 2:158, 3:42, 4:9, 5:2}
```

### 2種類の曖昧さを外している

外さないと、**モデルの正しい別解を誤りと採点します。**

| 曖昧さ | 例 | 扱い |
|---|---|---|
| 循環 | 鉄インゴット ⇄ 鉄ブロック ⇄ ナゲット | 探索中スタックに載る材料を要求する作り方を選択肢から外す。全部外れたら葉 (鉄インゴットは実際には製錬で得るのでこれが正しい) |
| 分岐 | 「どの木材でも可」「どの色の羊毛でも可」 | 材料集合が2通り以上あるものは除外 (439件) |
| 葉が可craft | 小麦9個 ⇄ 干草の俵 | どこで止まるのが正解か決まらないので除外 (57件) |

### 課題文は止まる場所を例で書く

「作れないものまで展開せよ」とだけ書くと、**モデルが精錬の1段先まで正しく展開した答えを
誤りと採点します。** 1回目の実験はこれで丸ごと捨てました。

```
Stone Pressure Plate   誤った正解 stone   モデル cobblestone   ← stone は cobblestone を精錬
Glass Bottle           誤った正解 glass   モデル sand          ← glass は sand を精錬
```

## 限界

- **L4 は9問、L5 は2問。** 深い側の数字は参考値
- **段数と難しさは一致しない。** L5 が高く出るのは `Bamboo Mosaic Stairs → bamboo` のように
  深いが答えが自明な問題だから
- 材料の「種類」の集合だけで採点していて、**個数を見ていない**
- 分岐と可craft葉を除いているので、対象は木材・石材系に偏る
- 温度0で各1回。ばらつきは測っていない
- **未計測を 0% と書かないこと。** `gpt-oss:20b` は think を切ると JSON を返さず、
  切らないと推論だけで出力上限を使い切って本文が空になる。集計は `## エラー` 行を見る
